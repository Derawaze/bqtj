# 独立开发工作方式

保留此路径作为已有 agent 入口。默认独立开发者与一个 agent 协作，按需求交付小增量，不要求角色分工、周会、固定 Sprint 或单独审批每个可逆步骤。

## 一次迭代

1. 从 [任务清单](backlog.md) 选一个结果明确的任务；同时进行的产品任务最多一个。
2. 用“结果 / 范围 / 验收”三行明确本次增量；小改动直接写在任务项里，不另建方案。
3. 只读相关模块。存在关键未知时先做一个有界探针；缺陷先得到可重复的失败信号，再修复。
4. 完成一个可运行、可验证的纵向改动。先跑相关验证；影响公共行为或交付包时再跑全量及必要实机验证。
5. 交付结果、证据和未验证范围。通过后移出活动清单；用户新反馈进入下一增量，不堆成大版本重写。

任务过大时拆为各自能验收的小步；每步只包含一种主要行为变化。不按时间凑任务，不预估远期细节，不把候选想法写成承诺。

## 文档只写一次

| 信息 | 唯一维护位置 |
|---|---|
| 当前基线、接手动作 | 根目录 NEXT_AGENT.md，建议40行以内 |
| 稳定术语、用户约束 | 根目录 CONTEXT.md，建议40行以内 |
| 优先级、当前任务、验收条件 | backlog.md，“当前”1项，“接下来”不超过3项 |
| 命令与验证选择 | development.md |
| 模块职责和关键边界 | architecture.md |
| 难以重建的故障证据 | diagnostics/，按问题查阅 |
| 已交付版本证据 | 对应 release-v*.md，不复制到各处 |
| 重大长期决策 | decisions.md；普通实现选择写代码注释 |

这些行数是压缩提示，不为凑指标丢失关键事实。任务结束就地改写状态，禁止在开头不断叠加“最新进展”。

## 按需深入

- 默认只读入口三份短文档，再读本次任务项及相关代码；通过路径/符号搜索定位。
- 小改动不用长计划、独立决策文档或工作日志。只有跨模块、不可逆或多轮研究才补短方案，结束后提炼结论。
- 已知测试通过后，未改相关逻辑就不重复跑；文档修改仅做结构、链接、事实检查。
- 事实、推测和待验收分开。进入游戏菜单不等于战斗、长时运行或全部DPI场景已验证。
- 过时方案直接删除，有效原因收敛到当前决策；不默认重读所有 diagnostics/。
- 用户提出并行工作时才拆任务，并约定文件范围；不为流程本身增加 agent 或交接文档。
