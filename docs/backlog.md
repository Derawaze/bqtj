## 脚本功能：多账号日常

### 已确认的产品要求

- 面板保留上次运行方案的一键启动入口；独立窗口管理脚本、方案与运行进度，提供停止操作。
- 启动器同目录使用 `scripts/` 存放脚本；用户放入脚本包后可自动识别、查看与管理，识别不会自动执行。初版建议每个脚本一个目录，包含清单、流程和识别图片，不承诺运行任意语言脚本。
- 按面板账号名称选择一个或多个账号；每账号可多选1—8号存档，选择区为两列四行。显示“账号名称－存档号”，内部使用账号Guid与存档号，改名不丢失绑定；实际格子与存档编号对应关系须实机确认。
- 本地保存有名称的运行方案，包含脚本、账号与存档、倍率及并发设置。个人方案与脚本资源分开保存，更新脚本不覆盖方案；凭据仍由启动器管理，不复制到脚本包。
- 不同账号并行，同一账号的多个存档依次运行。首版建议默认并发2，受现有会话总上限约束；同一平台账号的不同记录不承诺可同时登录。
- 必须不抢鼠标、键盘和前台焦点。首版允许游戏窗口被遮挡，暂不保证最小化或锁屏后继续；不可控制时暂停，不偷偷回退到前台点击。
- 用户先在各存档配置好游戏内置脚本“日常操作复制”，启动器不负责创建或修改它。
- 视觉引擎使用独立脚本组件包分发，基础启动器保持精简。

### 首个脚本流程与完成规则

进入账号并完成现有自动登录 → 等待存档界面 → 选择指定存档 → 点击“助理” → 选择“日常操作复制” → 点击下方运行按钮 → 在弹窗点击确定 → 确认开始 → 等待官方脚本执行 → 确认最后保存完成 → 关闭本次账号窗口 → 执行该账号下一个存档。

- 官方脚本最后一步打开系统设置，等待“保存存档”60秒冷却结束后点击保存。冷却与保存由官方脚本负责，外层只观察；不得因为设置页出现、按钮可点击或画面静止就判定完成。
- 候选完成判据：本次已观察到运行开始，右侧“日常操作复制”的已执行数等于总数（示例22/22，不写死22），最后一项“保存存档”显示绿色对勾；连续识别确认后再留出关闭前缓冲。识别次数、间隔及缓冲时长在第一步实机验证后固定。
- 用户已确认：中间任务出现红叉不阻止后续存档；只要最后保存成功，就记录“已完成，有未成功项目”并继续。红叉不等于整个批次失败。
- 绿色对勾是待验证的画面判据，不等于已证明服务端持久化。需对照正常保存后的重新进入结果，检查是否存在保存失败却显示完成的情况。
- 建议默认：登录、菜单操作保持原速，确认内置脚本开始后使用方案倍率；复用当前倍率范围，不直接默认100倍。调度超时使用真实时间，不按Flash倍速缩短60秒冷却。
- 保存未确认、验证码、掉线、缺少内置脚本或识别超时：保留窗口，暂停该账号后续任务并提示原因；其他账号可继续。不能把超时标记为成功，不自动重复点击运行或重跑整个任务。
- 自动化仅关闭本次创建的会话；已有手动运行窗口默认跳过并提示，不接管、不关闭。停止时停止新操作、释放按键、恢复运行前倍率并保留窗口；停止外层调度不保证游戏内置脚本也已停止，应明确提示用户。

### 增量顺序与验收

1. **后台能力与结束信号验证**：先观察正常运行、红叉但保存成功、保存等待/异常三类过程；采集仅含所需游戏界面的识别素材。验证两个账号被遮挡时截图持续更新、输入只作用目标窗口、鼠标及前台焦点不变；同时确认存档布局、完成信号和关闭前保存稳定性。后台能力失败就记录阻碍，不先铺完整管理界面。
2. **单账号单存档闭环**：接通账号启动/关闭、会话绑定、截图、识别、定向输入及倍速控制；逐步验证流程与完成规则。只有真实观察到本次执行和保存完成才能自动关闭。覆盖取消、窗口意外关闭、无响应及清理，不遗留工作进程。
3. **方案与多账号调度**：加入脚本目录识别、管理窗口、两列四行存档选择、本地方案和面板快捷启动。验证不同账号并行、同账号串行、重命名/删除账号、重复启动、已有会话、脚本包缺失/格式错误及运行中替换脚本（仅下次运行生效）。
4. **开发包验收**：验证100%/150%窗口比例及不同DPI下坐标对应，后台遮挡、最小化/锁屏暂停、用户继续操作其他软件、红叉后正常推进、保存超时保留窗口、面板退出与任务清理；完成用户验收后再讨论正式发布。

测试使用合成画面/状态覆盖状态迁移、总步数变化、旧完成画面、红叉与最终保存的组合，以及并发互斥、取消与配置持久化。Flash后台兼容性、官方脚本结束和重新进入后的存档结果必须实机验收，不能由模拟测试替代。具体构建与操作命令仍只维护在 [开发手册](development.md)。

### 技术方向与待验证项

- 优先验证MaaFramework，成功后复用其图像/OCR识别与流水线。使用定向窗口输入，不依赖固定延时或桌面绝对坐标；坐标以实际游戏视口为基准，处理缩放、黑边与DPI。
- 现有 `IGameSession` 仅有激活、关闭及生命周期，没有截图/输入/倍速的面板控制接口。新增独立自动化会话接口，通过会话ID绑定目标、报告阶段与错误；游戏就绪不能仅用进程创建或宿主就绪代替。
- 候选结构为x86启动器/Flash宿主加独立x64视觉工作进程，通过本地IPC协作，不把x64库加载进x86进程。MaaFramework v5.14.2官方Windows x64压缩包约69.7MiB，未提供Windows x86资产；采用该方向时脚本组件要求64位Windows。冻结依赖版本前确认兼容性与分发内容。
- 必须先验证Flash后台截图与不抢焦点的输入；框架支持Win32后台方式不代表本游戏已经兼容。不得使用会抢鼠标的兼容模式来满足后台验收。
- 脚本清单需包含稳定ID、名称、版本、入口和兼容要求；发现缺失依赖或非法包应显示不可运行原因。首版只提供受控动作，不开放任意进程执行、凭据访问或任意文件操作。
- 自动化日志记录阶段、耗时、失败原因及最终保存结果，接入现有脱敏诊断工具；不写凭据，默认不导出原始游戏截图。
- 收费、授权服务器、防复制及地图拾取/战斗自动化不纳入首版。后续地图识别可复用视觉接口，但路径、攻击与时机规则另行迭代；收费与闭源需结合本项目GPLv3、MaaFramework LGPLv3及实际集成关系单独评估。
