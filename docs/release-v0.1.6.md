# v0.1.6 热更新开发包（F3 改为窗口级热键）

日期：2026-09-26。用户实机反馈：v0.1.5 账号能正常进游戏，但 F3“不论怎么按都无法切换”。本轮定位并改用窗口级热键；**用户已实机验收通过**。v0.1.5 发布包已按要求删除。

验收结论：F3 在游戏内可用（不点击画面即可互换），验收通过后代码提交入库。本轮交付物为开发包 `artifacts/dev/BqtjLauncher-v0.1.6-win-x86.zip`，未生成 release 正式包。

## 排查过程与结论

在容器里逐个窗口注入按键后，日志给出了确定答案：

| 注入目标窗口 | 宿主钩子是否收到 |
|---|---|
| 容器表面窗口（WPF/WindowsFormsHost） | 收到 |
| 原生宿主窗口 `BqtjNativeFlashHost` | 未收到 |
| `AtlAxWin` / `Shell Embedding` / `Shell DocObject View` | 未收到 |
| `Internet Explorer_Server` | 未收到 |
| `MacromediaFlashPlayerActiveX` | 未收到 |

结论：**宿主进程内的消息钩子不可靠**。先试的 `WH_GETMESSAGE` 与后试的 `WH_KEYBOARD` 都只在按键落进 WPF 表面窗口时触发；真实按键在游戏画面里由 IE/Flash 直接取走，钩子看不到，所以 F3 静默失效（按键既没被上报，也没被吞掉）。宿主钩子与配套的 `recent-speed-key` 管道上报已整体删除。

同时发现两处工程问题并已修正：

- 容器的 Serilog 从未初始化，容器侧的启动/诊断日志全部被丢弃；现在容器与面板写同一个日志文件（问题不在渲染，而在日志全程没有落地，导致上一轮只能靠猜）。
- 交付宿主只在你反馈后才需要重建：本轮原生宿主回到不装钩子的状态，体积从 119,808 回到 117,760 字节。

## 改动

- 容器窗口改用 `RegisterHotKey(handle, id, MOD_NOREPEAT, VK_F3)` 注册**窗口级热键**：系统在容器窗口处于前台时投递 `WM_HOTKEY`，与键盘焦点落在哪个子窗口无关，游戏画面持有焦点时同样有效。
- `WM_HOTKEY` 不是普通按键，子窗口收不到，不会与游戏自身按键冲突。
- 焦点在 WPF 侧时原来的 `PreviewKeyDown` 仍保留；两条路径共用 `OnF3HotKey`。
- 按住 F3 时 `WM_HOTKEY` 会连续投递，加 300ms 保护窗口去重。
- 热键注册失败（被其它程序占用）只记日志并退回 WPF 路径，不阻止启动；窗口关闭时 `UnregisterHotKey`，避免同账号二次启动容器注册失败。
- 新增诊断（写入 `%LOCALAPPDATA%\BqtjLauncher\logs`）：热键注册结果、每次 F3 到达、每次互换的前后档位、宿主每行输出。

## 验证范围

- .NET 测试 72+13 通过（删除了针对已废弃管道事件的测试）。
- 容器内端到端：向容器窗口投递与生产一致的 `WM_HOTKEY`，UI 自动化读到“变速”提示由 5倍 变为 原速，日志同时出现 `收到 F3：... previous=1` 与 `F3 互换：5倍 → 原速`。
- 本机无法注入真实键盘（`SendInput` 返回错误 87，被环境拦下），因此**未能**用真实按键复现；窗口热键是系统级机制，理论上不依赖焦点。
