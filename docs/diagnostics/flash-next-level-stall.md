# Flash 下一关加载卡死调查

## 当前证据

- 当前仓库没有 1 GB 内存上限、Job Object 内存限制或工作集上限配置。
- 旧启动器与当前桌面宿主均是 32 位进程，地址空间压力可能放大 Flash/ActiveX 的本机内存泄漏或碎片问题，但不能据此确定根因。
- 旧启动器包含 `RunDll32.exe InetCpl.cpl,ClearMyTracksByProcess`，用于手动或账号启动阶段清理 IE 浏览数据；没有证据表明它会在关卡切换时释放 Flash 原生内存。
- 清理 IE 浏览数据可能删除共享 Cookie/登录态；`EmptyWorkingSet` 只会修剪工作集，均不适合作为未经验证的自动修复。

## 本轮处置

管理面板新增“重启所选账号容器”。该动作从容器外部关闭进程；若 5 秒内不能正常退出则强制终止，然后重新启动同一账号容器。进程退出会回收 Flash、IE ActiveX 和本机堆的全部内存，也不会影响其他账号容器。

这是一条安全、确定的恢复路径，不代表随机卡关的根因已经修复。要定位根因，需要在再次复现时采集该容器进程的时间序列（CPU、Private Bytes、Working Set、句柄数）或进程转储，并记录卡死发生时间和账号名。
