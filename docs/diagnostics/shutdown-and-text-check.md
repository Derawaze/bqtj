# 关闭面板后的进程残留

2026-09-28：现场发现旧 v0.1.6 开发包两个 Desktop 进程窗口句柄均为0，没有原生 Flash 宿主残留；未读取进程内存、账号库或日志，未主动结束现场进程。

## 可重复证据

面板 App.OnExit 同步等待 ServiceProvider.DisposeAsync；LauncherModule.DisposeAsync → CloseAllAsync → FlashGameProcessSession.CloseAsync 原先捕获 WPF 上下文。子进程异步退出后，续体仍等待正在同步阻塞的界面线程。

`GameSessionShutdownTests.CloseCompletesWhenCallerStopsPumpingDispatcher` 使用真实会话关闭代码、无账号的临时子进程和停止泵消息的 STA 上下文：修复前3秒超时失败，修复后约1秒通过。LauncherModuleTests 补充异步会话关闭的整层释放回归。后续扩展为短任务正常退出与长任务5秒超时终止两条路径，连同整层释放共3项定向回归通过；测试同时确认临时子进程确实退出。

修复：进程退出等待、会话集合关闭、模块释放均使用 ConfigureAwait(false)，避免退出链返回界面线程。85项应用测试通过。此证据锁定一个可产生相同残留现象的缺陷；未读取旧进程调用栈，不宣称排除了全部退出阻塞。真实游戏启动后关面板的最终验收待用户完成。
