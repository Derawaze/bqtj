# 脚本目录

将单个 JSON 文件或含 script.json 的脚本目录放到这里，脚本管理窗口会自动发现，不会自动运行。

用户方案保存在 plans/，明文记录账号 ID、存档号和名称、排序、倍率、并发数及关窗选项，不含账号密码。覆盖更新请保留 plans/ 和自己添加的脚本。

每个账号自带的日常默认绑定“本账号”的稳定ID；首次运行自动读取并更新八个名称，再选择两列四行中的存档，待选择存档会直接改写为存档1～存档8。之后可以编辑源码，取消保留扫描名称和窗口，不改写方案；作为子方案时也先完成选择。初始化记录在config/account-daily-created.json，删除自带日常后不重新生成。复制日常成为普通方案，不占用账号默认入口。

新版编辑器将中文语句及绑定保存为plans/中的version=2方案。每行一条操作、英文逗号分隔参数，支持日常操作、读取存档名称、启动存档、退出存档、关闭窗口、调用及并行开始/并行结束。普通语句顺序执行；同账号多存档放进同一个子方案，不同账号子方案可显式并行。读取名称完成保留窗口，日常接管本面板已有窗口并切换到指定档；结束时不自动关窗，需要时插入“关闭窗口,账号”。

全局常量在config/constants.txt，右栏编辑后单独保存，所有方案及子方案均可使用；本方案同名覆盖值随方案保存并优先。常量可选、可留空；每行“名称=值”，例如日常档=存档5，语句中以$日常档引用，修改一处即可复用。已有方案的常量保留为本方案覆盖值，需留空才采用同名全局值。账号/子方案通过稳定ID绑定，改名可选择同步所有引用；运行时冻结完整调用树，编辑只影响下次。旧v1方案仍保留原语义，日常可复制为新版顺序语句。

语句或常量有错误也可保存，原文保留，运行前才强制校验。在脚本开头声明“方案设置,子方案,是”和“方案设置,面板可见,否”，分别决定能否被调用及主面板可见性；子方案仍可单独运行。声明在所有操作前且不得重复。没有声明的旧方案沿用showOnDashboard，isSubPlan默认true兼容旧调用；新方案默认不是子方案、面板可见。

内置模板与用户方案统一保存在plans/，可直接编辑，名称后有“（内置模板）”。内置为单账号多档日常、并行调用两个子方案、全局常量示例；读取名称的单独内置模板退役，操作本身仍保留。方案设置和日常操作说明在注释中。保留.built-ins-v1/.built-ins-v2标记；升级保留已编辑内容，不恢复删除。草稿的常量原文保存在constantsSource，旧方案的constants字典仍可读取。

存档显示资料保存在catalog/，读取后可以校正，名称不参与实际选档身份。覆盖更新保留plans/、config/、catalog/及自定义脚本；开发验收包内测试方案清理时无需备份。游戏窗口可以遮挡，但不能最小化。

日常优先调用游戏内置的“日常操作复制”，列表没有时选择“日常操作”。可写成`日常操作,账号,存档5,我的日常`指定游戏内的准确名称，第四项也能使用常量；填写后只选择该名称。最终保存仍由游戏脚本完成，启动器观察所选名称的本次进度增长，再确认右侧整体N/N标题左侧绿色勾持续至少3秒；列表末行可以不在视口内，不能用画面静止代替完成判断。进度增长包含22/23直接到23/23；暂停或中间漏读不会抹掉此前的未完成进度，完成确认仍需新的连续截图。

日常按同账号的下一条操作完成自己的收尾：同档操作由当前日常关闭系统页并收起官方侧栏；换档、读取名称或退出由当前日常先退出存档，收尾后才标为完成。没有后续操作则保留完成画面，显式关闭窗口直接关窗。跨账号语句和子方案不改变这一规则。

刷材料只处理自己的地图与关卡入口。选择正常模式后，只有看到难度页才继续；原模式面板仍清楚可见时最多重试3次。异常后继续可接着处理本关模式或难度页。单独运行时若手动打开了系统或侧栏，请先收起。

脚本运行日志在`%LOCALAPPDATA%\BqtjLauncher\logs\script-日期.jsonl`，主面板“打开日志目录”可以直接打开。日志记录运行/会话编号、固定菜单识别及置信度、坐标、点击发送/回执、等待与超时，不记录账号密码、方案源码、任意OCR正文或截图。按天及2MiB滚动，最多保留7份。出现卡住时保留游戏现场和对应时段日志即可。

新版中文方案在监控栏支持“暂停”和“继续”。手动暂停保留当前步骤，停止发送后续外部输入，恢复时重新截图定位；正在发送的短按键会正常松开。游戏内置日常和AI可能仍在运行。异常或停止后点击继续，会使用本次冻结快照重试未完成语句，已完成语句和并行分支不重跑；刷关次数从当前语句重新计数。继续记录只保留在本次启动器进程中，重新打开启动器后需要重新运行方案。编辑方案不修改这份快照，要运行修改后的内容请点击“运行方案”。旧版v1队列可复制为中文方案使用这些控制。

JSON 使用 version: 1，id 是唯一脚本标识，name 是显示名称，entry 指向 flow 内的起始步骤 ID；步骤按数组顺序执行。

支持的步骤：officialDaily、enterSave、waitText、clickText、waitImage、clickImage、click、wait、waitOfficialCompletion。

- 文字步骤使用 text；图片步骤使用包内相对路径 image。
- roi 为 [x, y, 宽, 高]，默认整个950×600画面。click 使用 x、y；识别点击可附加 offsetX、offsetY。
- 界面等待默认 timeoutSeconds: 120；wait 使用 milliseconds，默认1000。
- enterSave 进入方案指定存档；officialDaily 包含选档、打开助理、启动日常与最终保存观察。
- waitOfficialCompletion 必须实际观察到本次日常进度增长，再持续确认最终保存；不能观察一个已经结束的旧画面直接完成。

标题先出现而卡片尚未绘制完整时，会等待完整八张卡片再识别或选档，期间不重复点击；持续不匹配保留窗口。识别失败或窗口不可用时保留游戏供人工处理；“停止队列”只停止启动器的外部操作，内置脚本可能仍继续运行。

“刷取每日材料”默认天空顶、地狱四、刷满，需要协议7视觉组件，当前已由用户确认为初代可用。每日限额识别仍待改进，读不到时不会自动停刷；也可指定正整数次数。无总统时，仅第10轮及以后、通关首屏没看到优先材料时检查限额；前9轮不查，有材料的轮次先拾取，拾取后不额外检查。冷冻宝石/守护宝石共享上限和冥王图鉴两项都满且绿色时结束。限额不可读就继续刷取，任何次数的空屏都不再作为退出理由。后台悬停在截图前和截图等待期间续发，不移动系统鼠标；需配套带悬停刷新的协议7组件。指定次数模式不查限额，其他关卡尚未实现。

通关后背包按钮上有“满”时，先到武器页一键拆解并确认结果，再到装备页重复；基因体标签上方有“满”才一键分解并确认。分类、操作按钮和弹窗每次观察前后台悬停到背包标题，再重新截图，避免装备详情遮挡。确认框和结果框按固定位置点击，用按钮布局判断切换，不等待“拆解完成”等文字OCR，切换时每50ms观察一次。游戏已有的品质/保留条件保持当前选择，没有可拆物品也确认后继续；关闭背包再开始拾取。补捡中仍有材料且背包再次满时，也会整理后继续有限补捡。整理逻辑在刷关共用模块中；限额识别需配套协议7组件。

天空顶先上升、再沿顶向右。协议6在一次请求中同时按N/W，N在50ms后释放，W完成首个上升短按；只有确认AI原本开启才切换，原本关闭则正常上升。首段W也计入1.2秒总上限。小地图黄点代表操控角色，绿点是队友；ROI从波次文字下沿开始，当前为(831,21,74,44)，旧y=25会漏掉顶部黄点。黄点可提前确认到边，无黄点时仍可参考上沿血条；耗尽按键预算就按已到达继续。sweep中maxRiseMilliseconds=1200、maxRightMilliseconds=3500，可配合pulseMilliseconds调整。首帧及累计移动每360ms检查目标，见到宝石或图鉴就提前转入当前可见区域拾取；血石仅辅助邻近目标定位，不单独追逐或阻塞完成；未见目标就重玩或按次数退出。

掉落图标和关卡拾取规则位于resources/loot，下一次运行读取更新后的catalog.json与PNG；三个宝箱全关卡拾取，其他目标按关卡和用途选择。只更新图片、已有规则和已支持的方案不必重构主程序；新增语法、刷关流程或底层走位能力仍可能要更新主程序/视觉组件。合并更新scripts时保留plans、config、catalog和自定义目录。

守护宝石和图鉴包含多种真实堆叠本体，guard-pile-battle.png及两张overlap图案覆盖血石/枪械遮挡，原匹配门槛不变。六帧旧堆叠现场与本轮两帧无遮挡新堆叠回归均保留，被抽奖栏遮住的画面不能作为目标。图片本身可独立更新；本轮局部路线和限额修复还需主程序及协议7组件。已暂停任务持有旧快照，停止本次运行后新运行才加载更新。大雨及完整动态拾取仍待实机验收。

拾取时不再下移找被抽奖遮住的人物。人物可定位才提前结束上/右搜索，短按校准避开边界；已看到的目标不会因一两帧漏识别被丢弃。局部材料区域先靠近左上侧，再只走右、下、左一轮，向右宽度为材料区域的2.4倍、下降保持原首行间距，不追加退让路线；连续复查两帧为空才结束；还有材料显露则继续当前区域，最多三次，持续残留时保留窗口。

难度采用正常模式的两列五行固定按钮位置，不再读取被悬停说明遮住的按钮文字。支持简单、普通、困难、超难、冲刺、炼狱、地狱、地狱二、地狱三、地狱四；未登记名称在游戏操作前报错。冷冻宝石加入本体纹理核验，青色晶面只扩展已确认宝石堆，避免蓝色装置及出口光效误报。该规则需要本轮主程序与resources/loot一起更新，仅换图片无法修复旧程序的纯颜色判定。

重玩关卡固定点击(470,309)，对应确认弹窗出现后固定点击(420,315)，无需识别重玩按钮和确定按钮文字；与一键拆解同为共用操作，供其他刷关语句复用。限额读取先用普通文字识别名称，蓝色/绿色比例遗漏时，再从同一截图裁出名称右侧的小数字读取，绿色状态仍取原图；本轮主程序需配套协议7组件。

账号总统设置由新增/编辑账号和账号管理工具管理，所有存档共用，默认无总统。方案运行时固定该账号设置，无需修改语句。有总统时通关后等约1秒自动拾取和拆解，不关闭AI、不走位、不打开背包；刷满模式第10轮起每轮查询两项限额，固定次数不查。两种模式均不使用空屏保底。蓝色为未满，达到或超过上限变绿，两项计数和绿色都满足才结束。到期或续费后手动调整，下次运行生效。
